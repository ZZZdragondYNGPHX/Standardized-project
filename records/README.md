# Records

Records are permanent executed-task history.

Use semantic subdirectories matching the task's Primary Workspace, such as:

- `feat/`
- `fix/`
- `refactor/`
- `package/`
- `plugin/`

For a multi-stage task, update the same Record after every completed stage. Preserve earlier stage facts instead of reconstructing them at the end.

A stage record should normally include start/end HEADs, completed work, key decisions, validation/CI, known limitations, and the next trusted checkpoint.
