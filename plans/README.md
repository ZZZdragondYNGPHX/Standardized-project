# Plans

Plans document intended design and rationale before or during implementation.

Use semantic subdirectories such as:

- `feat/`
- `fix/`
- `refactor/`
- `package/`
- `plugin/`
- `architecture/`

A small localized task may have no Plan. Larger features, architecture/refactors, complex assets/tools, or work explicitly discussed before implementation should have one.

Update a Plan only when the approved design materially changes.
